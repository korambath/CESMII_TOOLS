Step 1. Create a subscription with body

{
  "clientId": "mqtt_test_client",
  "displayName": "BME280 MQTT Subscription"
}


curl -s -X POST http://localhost:8080/subscriptions \
-H "Content-Type: application/json" \
-d '
{
  "clientId": "mqtt_test_client",
  "displayName": "BME280 MQTT Subscription"
}' | jq

Response


{
  "success": true,
  "result": {
    "clientId": "mqtt_test_client",
    "subscriptionId": "ac9c3b08-9887-4bb0-9871-5e017a9e521c",
    "displayName": "BME280 MQTT Subscription"
  }
}

What this does

This creates a new subscription object on the server.

Think of it as opening an empty mailbox.

At this point the subscription contains no sensors.

Subscription
├── ID: ac9c3b08-9887...
├── Client: mqtt_test_client
└── Watching: nothing

subscriptionId =
ac9c3b08-9887-4bb0-9871-5e017a9e521c

Step 2. Register an object with the subscription
POST /subscriptions/register

curl -s -X POST http://localhost:8080/subscriptions/register \
-H "Content-Type: application/json" \
-d '
{
  "clientId": "mqtt_test_client",
  "subscriptionId": "ac9c3b08-9887-4bb0-9871-5e017a9e521c",
  "elementIds": [
    "cesmii_labLA_bme280sensor"
  ]
}' | jq

Response


{
  "success": true,
  "results": [
    {
      "success": true,
      "elementId": "cesmii_labLA_bme280sensor",
      "subscriptionId": null,
      "result": null,
      "responseDetail": null
    }
  ]
}

What this does

Now you're saying

"Please associate this sensor with my subscription."

The subscription changes from


Subscription
└── nothing

to

Subscription
└── cesmii_labLA_bme280sensor

Now the server knows

Whenever this sensor changes,
send it to this subscription.


Step 3. Start streaming


POST /subscriptions/stream


{
  "clientId": "mqtt_test_client",
  "subscriptionId": "ac9c3b08-9887-4bb0-9871-5e017a9e521c"
}

This is the step that says

"Open the mailbox and keep it open."

The server keeps the HTTP connection alive.

Instead of replying once and closing the connection, it continuously sends events.
